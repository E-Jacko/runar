## Detection point

| | |
|---|---|
| Documented (docs/sp1-fri-verifier.md §6) | Colinearity check |
| Actually observed | FRI commit-phase MMCS opening (NOT a standalone colinearity check) |

Rejection message:

```text
verify: FRI: fri: query 0: round 0 MMCS: verify_batch: cap mismatch at idx 0
```

DIVERGES from the documented "colinearity check". Plonky3 FRI has no
standalone colinearity assertion: every value the fold consumes is
Merkle-committed, so `VerifyBatchExt` for the commit-phase round fires
strictly before any folding arithmetic runs. The colinearity property is
enforced *by* that commitment check plus the final-poly equality, not by a
separate reachable check. See the corruptions README "Detection-point
reality" section.
